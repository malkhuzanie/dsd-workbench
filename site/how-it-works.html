Product · How it works

See what happens inside, step by step.

Four short chapters on what the workbench does between "Split" and "identical": drawn from the program's own rules. Scroll to move through them.

1Read

One long stream, untouched.

A DSD side is a header, a stream of 1-bit samples and an ID3 tag. The workbench reads the header and the tag, parses your CUE sheet, and never opens the source for writing.

  • DSF and uncompressed DSDIFF, any channel count, any DSD rate
  • CUE text in UTF-8, UTF-16, Shift-JIS, Windows-1252 and more
  • Missing or misnamed files are relinked, never guessed
2Cut

Cuts land on the exact sample.

Each track starts and ends on the sample the plan names, and neighbouring tracks tile with no gap and no overlap, even when a cut falls in the middle of a byte.

  • Cut points from the CUE sheet, by hand, or from silence detection
  • A cut that lands in loud music is flagged before you split
  • Nothing is written yet: this is only the plan
3Write

Each track becomes its own file.

Every track gets a fresh DSF header and its own ID3 tag around the copied audio. It is written to a temporary file and renamed into place only when complete, so a cancel or a crash never leaves half a track.

  • DSDIFF's bit order is reversed so output is always standard DSF
  • Tags and cover art are written per track
  • Existing files are never replaced unless you allow it
4Verify

Then it checks its own work.

Each output is read back and compared with the source, sample by sample. Differences are mapped; a file that is right but shifted is detected; headers, tags and cover art are checked too. Scripts get a real exit code.

  • Identical / differs / missing, per track
  • Integrity map of where any difference is
  • --verify and --verify-only on the command line
·Try to fool it

One flipped bit is enough.

Verification compares every bit of every channel. Flip a single bit in the copy and watch the comparison find it, and tell you where.

This sketch uses a small synthetic stream; the real thing does the same over gigabytes, and shows the result as an integrity map per channel.

·Under the hood

Why it can be this exact.

No decoding means no loss

DSD is already a 1-bit stream. Converting to PCM and back changes it. Copying the right bits changes nothing: the output audio is the source audio, bit for bit.

Cuts are in samples, not bytes

A cut can fall inside a byte. The writer shifts the bits so each track starts on exactly the sample you chose, and pads the final block the way DSF requires.

Every write is atomic

Audio goes to name.dsf.part and is renamed on success. A failed or cancelled track leaves no partial file behind.

Tested against an oracle

The test suite splits synthetic DSF and DFF files with awkward cut points and checks every output bit against a separate reference implementation, and fuzzes the parsers.

Convinced? Cut something.

It builds with one command. Binaries for Windows, macOS and Linux come with the first release.
